## بخش اول: تست نفوذ و بررسی امنیتی

### روش کار
۱) **بازبینی کد**: احراز هویت، مجوزها، CSRF، کوئری‌ها، خروجی‌ها، آپلود/دانلود فایل، کوکی و نشست، خروجی اکسل.
۲) **حمله زنده** روی سرور در حال اجرا: SQLi در فرم ورود، POST بدون توکن CSRF، XSS ذخیره‌شده، پیمایش مسیر (Path Traversal) در دانلودها، بروت‌فورس ورود و ورود با کد شرکت‌کننده، دسترسی به فایل‌های حساس (`.env`، `.git`، دیتابیس، لاگ)، بررسی هدرهای امنیتی.

### ✅ چیزهایی که تست شد و پاس شد (با شاهد)

| مورد | نتیجه تست زنده / کد |
| --- | --- |
| **SQL Injection** | همه کوئری‌ها با binding پارامتری (`whereRaw('LOWER(username) = ?', [...])`)؛ تزریق `admin' OR '1'='1' --` در ورود → بدون عبور (۳۰۲ و شمارش خطا) |
| **CSRF** | همه فرم‌ها `@csrf` دارند؛ POST بدون توکن → **۴۱۹** |
| **XSS ذخیره‌شده** | نکته با عنوان `<script>alert(1)</script>` ثبت و در صفحه عمومی دیده شد → **escape شده** (`&lt;script&gt;`)؛ `RichText` اول `e()` می‌زند بعد مارک‌داون |
| **بروت‌فورس ورود پنل** | RateLimiter روی IP+نام‌کاربری (۵ تلاش/۶۰ ثانیه) — در عمل تلاش ششم **بلاک شد** |
| **Session Fixation** | بعد از ورود موفق `session()->regenerate()`؛ خروج با POST + `regenerateToken()` |
| **کنترل دسترسی پنل** | بدون ورود → ۳۰۲ به لاگین؛ هر مدیر فقط چالش‌های خودش (`visibleToAdmin`)؛ داده دیگران ۴۰۳/۴۰۴ (تست خودکار دارد) |
| **داشبورد شرکت‌کننده** | کلید، توکن ۸ کاراکتری با `random_int` (CSPRNG) از الفبای ۳۱ حرفی ≈ ۸۵۲ میلیارد ترکیب؛ حدس‌زدنی نیست |
| **فایل‌ها** | بیرون از پوشه عمومی (`local` disk) با نام hash شده؛ دانلود فقط برای چالش منتشرشده و روز باز؛ **تراول `../../../../etc/passwd` → ۴۰۴**؛ id ناموجود → ۴۰۴ |
| **فایل‌های حساس از وب** | `.env` → ۴۰۴ · `.git/config` → ۴۰۴ · `database/dev.sqlite` → ۴۰۴ · لاگ‌ها → ۴۰۳ |
| **هدر Content-Disposition** | نام فایل با `rawurlencode` → امکان Header Injection نیست |
| **خروجی اکسل** | سلول‌ها shared-string (`t="s"`) و XML-escape هستند → **Formula Injection ممکن نیست** |
| **Mass Assignment** | مدل‌ها با `#[Fillable]` صریح (از جمله `Participant`) |
| **وابستگی‌ها** | `npm audit` → **۰ آسیب‌پذیری**؛ Laravel 13.35 (به‌روز) |

## بخش دوم: برای فروش سایت چه چیزهایی را باید در نظر گرفت

### ۱) آماده‌سازی فنی قبل از تحویل
- همان ۴ یافته متوسط بالا اصلاح شود (گزارش امنیتی تمیز = برگ برنده فروش).
- `APP_DEBUG=false`، `APP_KEY` یکتا، رمز مدیر اصلی قوی، HTTPS فعال.
- وب‌سرور واقعی (nginx/php-fpm یا LiteSpeed) — نه `artisan serve`؛ `upload_max_filesize/post_max_size ≥ 64M` برای صوت ۶۰ مگابایتی.
- **پشتیبان‌گیری**: فایل دیتابیس (SQLite/MySQL) + پوشه `storage/app` (فایل‌های آپلودی) + `.env`؛ یک اسکریپت/داکیومنت restore.
- حذف داده نمونه یا نگه‌داشتن دمو پشت پرچم (دمو برای فروش لازم است — جدا نگه دارید).

### ۲) مجوز و مدل درآمدی
- نوعlicence روشن: **فروش دائمی سورس** (یک‌بار پرداخت) یا **اشتراک/SaaS** (شما هاست می‌دهید) یا **لایسنس + پشتیبانی سالانه**. هر سه با این کدbase ممکن است.
- دامنه استفاده: یک دامنه/یک نصب یا نامحدود؛ انتقال حق مالکیت فکری یا واگذاری حق استفاده.
- قیمت‌گذاری: ارزش‌های متمایز این پروژه را در پیشنهاد بنویسید — ۲۳۱ تست خودکار، تقویم شمسی کامل، راست‌به‌چپ، خروجی اکسل ۷ برگی، چند مدیره با سطوح دسترسی، حالت تعمیر، آپلود صوت ۶۰ مگابایت با نوار پیشرفت، بدون وابستگی سنگین خارجی.

### ۳) مستندات (خریدار فنی این را می‌خرد)
- README فارسی کامل است؛ اضافه شود: **نیازمندی‌های سرور** (PHP 8.3+ با pdo_sqlite/mbstring/dom، Node برای build)، راهنمای نصب ۵ دقیقه‌ای، دستور `parvane:setup`، رویه به‌روزرسانی (`git pull` + `composer install` + `npm run build` + `migrate --force`)، رویه بکاپ/بازیابی.
- همین گزارش امنیتی + گزارش تست‌ها ضمیمه تحویل شود.

### ۴) برندینگ و وایت‌لیبل
- نام/لوگوی «پروانه شو» در favicon، لایه‌اوت‌ها و README است؛ اگر خریدار برند خودش را می‌خواهد، هزینه وایت‌لیبل جدا بگیرید. رنگ‌ها توکن‌محورند (`@theme`) → تغییر پالت ارزان است (تجربه‌اش را داریم!).

### ۵) پشتیبانی و SLA
- پله‌ها: نصب اولیه / رفع باگ ۳–۶ ماهه رایگان / توسعه اختصاصی ساعتی / به‌روزرسانی ماژور لاراول سالانه. مرز «باگ» و «فیچر» را در قرارداد روشن بنویسید.

### ۶) حقوقی و حریم خصوصی
- سایت **داده شخصی** جمع می‌کند: نام، راه ارتباطی، پاسخ پرسش‌ها، زمان فعالیت شرکت‌کننده‌ها → سیاست حریم خصوصی و شرایط استفاده لازم است؛ اگر به مشتری اروپایی می‌فروشید GDPR (حق فراموشی = حذف شرکت‌کننده وجود دارد ✓).
- مالکیت داده‌ها بعد از تحویل با مشتری است؛ در قرارداد قید شود.

### ۷) بازار هدف و کانال فروش
- **ایران (فارسی)**: مارکت‌پلیس‌های ژاکت/راست‌چین (کارمزد + نیاز به لایسنس‌گذاری دامنه) یا فروش مستقیم به مربی‌ها/مجموعه‌های آموزشی/برگزارکنندگان چالش. UI کاملاً فارسی است = برای این بازار آمادهٔ فروش است.
- **بین‌المللی (CodeCanyon و…)**: همه رشته‌های متنی فارسی و hardcode هستند؛ لایه ترجمه (lang files) و تقویم میلادی گزینه‌ای لازم دارد — این یک پروژه جداگانه است، نه تنظیمات.
- **دمو**: یک نصب زنده با دیتای دمو (`shokr-gozari-7` آماده است) + ویدئوی ۵ دقیقه‌ای از جریان کار (ساخت چالش → افزودن روز → شرکت‌کننده → خروجی اکسل).

### ۸) Due Diligence خریدار
- خریدار فنی این‌ها را چک می‌کند و شما باید جلو بیندازید: اجرای `vendor/bin/phpunit` (سبز)، `npm audit`/`composer audit` تمیز، کیفیت کد (`pint` اجرا شده)، تازگی فریم‌ورک، و همین گزارش امنیتی.
